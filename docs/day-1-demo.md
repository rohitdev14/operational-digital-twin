# Day 1 Demo — P&ID to Machine-Readable Knowledge

Day 1 asks a narrow question:

> Can we turn a P&ID into engineering knowledge that software can query?

The source of truth is intentionally simple:

- `assets.yaml` defines persistent engineering objects.
- `relationships.yaml` defines physical, measurement and control relationships.
- `query.py` traverses those relationships deterministically.

## Example queries

```text
What monitors P-101?
PS-101, PD-101, VT-101, EM-101

What is upstream of P-101?
P-101 <- ST-101 <- XV-101-S <- SH-001 <- TK-001

Which pumps discharge into DH-001?
P-101, P-102, P-103, P-104, P-105
```

These answers are not generated by an LLM. They are derived from the explicit
asset topology and measurement relationships captured from the reference P&ID.

## Run locally

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python knowledge/query.py
pytest -q
```

This is deliberately not a production knowledge graph yet. The purpose of Day 1
is to validate the ontology, IDs and relationships before introducing a graph
database, physics model or AI reasoning layer.
