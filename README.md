# Operational Digital Twin

[![Digital twin validation](https://github.com/rohitdev14/operational-digital-twin/actions/workflows/validate.yml/badge.svg)](https://github.com/rohitdev14/operational-digital-twin/actions/workflows/validate.yml)

Building a machine-readable engineering representation of a centrifugal pump system from first principles.

## Day 1 — Make the plant understandable

The reference system is an open-loop water supply system with **five parallel 30 kW VSD-driven centrifugal pump packages**, supplied from a common tank and discharging into a common variable-load header.

The Day-1 question is deliberately narrow:

> Can we turn a P&ID from a picture into structured engineering knowledge that software can query?

The first layer captures persistent asset identities, instruments, physical topology and explicit engineering relationships. It does **not** yet contain pump simulation, PID simulation, fault diagnosis, RAG or an AI agent.

## What is implemented

- `docs/system-definition.md` — system boundary and engineering assumptions
- `docs/pid/WSP-001_PID_V0.1.drawio` — editable conceptual P&ID source
- `knowledge/assets.yaml` — machine-readable asset registry
- `knowledge/relationships.yaml` — physical, measurement and instrumentation relationships
- `knowledge/query.py` — deterministic engineering queries over the knowledge layer
- `tests/` — validation of asset structure, relationships and query results
- `.github/workflows/validate.yml` — minimal CI that runs the test suite on pushes and pull requests

## Principle

**P&ID → assets → relationships → knowledge → engineering queries**

Every physical component receives a persistent identity. Measurements are linked to the assets or process properties they observe. The result is a small, explicit engineering knowledge layer rather than an attempt to make an LLM infer the plant directly from a drawing.

Example deterministic queries include:

```text
What monitors P-101?
→ PS-101, PD-101, VT-101, EM-101

What is upstream of P-101?
→ P-101 ← ST-101 ← XV-101-S ← SH-001 ← TK-001

Which pumps discharge into DH-001?
→ P-101, P-102, P-103, P-104, P-105
```

These answers are derived from the encoded topology and relationships, not generated by an LLM.

## Validate locally

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python knowledge/query.py
pytest -q
```

The validation suite covers both the knowledge layer and behaviour model. The same suite is run automatically by GitHub Actions.

## Scope boundary

Day 1 establishes the knowledge foundation only. Hydraulic physics, pump/system curves, VSD affinity laws, pressure-control simulation, synthetic telemetry and energy modelling belong to the next build stage.
